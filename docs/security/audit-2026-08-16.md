## Production-ready blockers (HIGH severity)

The following must be addressed before declaring this repo
"production ready":

1. **G108 pprof exposure.** The `net/http/pprof` package is imported
   unconditionally, which means `/debug/pprof/*` is exposed on
   the daemon's HTTP port. In production, this should be gated
   behind a build tag or a config flag.

2. **G115 integer overflow.** Three locations in
   promptsheon/store/sqlite_audit.go convert between int64 and
   uint64 without bounds checks. If a row's `row_id` exceeds
   math.MaxInt64, the conversion produces a negative value that
   then breaks the audit chain ordering. Add explicit bounds
   checks or use a different monotonic counter.

3. **G118 context.Background.** The goroutine dump writer uses
   context.Background instead of inheriting the daemon's request
   context. This means SIGQUIT-triggered dumps don't cancel when
   the daemon is shutting down.

4. **G124 insecure cookies.** OAuth state cookies are set without
   Secure, HttpOnly, or SameSite attributes. Required for any
   deployment that handles real users.

5. **G404 weak RNG.** The canary picker uses math/rand. As noted in
   PR 6 (v0.4.0 canary), the traffic-routing decision does not
   require a CSPRNG. Document this as an accepted trade-off or
   switch to crypto/rand.

6. **G703/G704 path traversal / SSRF.** Multiple locations accept
   file paths or URLs from user input without sanitisation. These
   are real attack surfaces in production.
